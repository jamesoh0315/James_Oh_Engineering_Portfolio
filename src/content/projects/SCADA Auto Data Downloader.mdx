At **Dometic Marine**, production data lives on the SCADA OT network, while the
Power BI reports that depend on it live on the IT network. Someone had to manually
export that data every day. I built the tool that does it on a schedule instead,
then rebuilt the interface around it.

## Overview

### The Problem

Inspection results, attainment figures, and machine tag history are all recorded on the
machine network, which had to be **manually downloaded for Power BI analysis**.

That was **repetitive**, and could leave the reports out of date if nobody remembered to run the export.

The existing manual downloader also crammed all of its functionality into a single window. Every
button repeated the phrase `from database to "C:\output"`, which pushed the actual dataset
name to the end. A raw OPC tag list, the database picker, and
the table picker all competed for the same screen.

## Automating the download

The automated job runs on the **IT gateway PC**, the one machine that can see both
networks, and pulls a configurable window of history into `C:\output` every night at
**3:00 AM**.

- **A timer script ticks every minute** and does nothing unless the hour is 3 and the
  minute is 0, a simple way to trigger the job at 3 AM every day.
- **The client gates itself by hostname.** At startup it checks which machine it
  is running on, enabling auto mode on the gateway PC and falling back to manual
  everywhere else.
- **An overnight job must never wait on a dialog.** Every message box in the auto-download
  path was replaced with console output, since a popup at 3 AM would block the run until
  somebody dismissed it the next morning.
- **A reboot failsafe.** Ignition starts checkboxes unchecked, so a gateway restart would
  bring the downloader back up with every dataset deselected, silently stopping it. The
  startup script instead force-selects them.
- **The settings window is deliberately kept open.** Ignition doesn't allow this type of
  window to be closed outright, so clicking outside it only minimizes it, which looks the
  same to the user as closing it. The components stay alive underneath because the timer
  script reads the schedule and dataset selections directly off them.

## Rebuilding the interface

The manual downloader was still worth keeping for flexibility. It was reorganized into **four tabs**: Quick Access, Tag History,
Database, and Auto-Download Settings.

Stating the `C:\output` destination once in a header, instead of on every button, improved
readability and left room to add more data types later.

## Outcome

Manual data retrieval is now **fully automated**. The selected datasets land on the
gateway PC every night at 3:00 AM, ready for Power BI to pick up. The manual path is
still there for one-off pulls, or to reach datasets outside the automated set.

### Challenges

- **The Ignition Designer learning curve** — the Vision module's scripting model and
  component hierarchy were both new to me.
- **Gateway deployment** — the gateway PC needed selective auto-login configured so the
  Vision client launches and signs in automatically on boot, while every other station
  keeps standard password login for security.
